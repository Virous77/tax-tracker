# Phase 1 importers

`importFile({ name, bytes }, { source, timezone, recipe? })` and the `binance`, `coindcx`, `generic` importer objects return synchronously. `readSheets` exposes decimal-string rows, `headerFingerprint` hashes normalised headers and sheet name, `applyRecipe` applies a validated recipe, and `recipeChecks` checks parsed dates/numbers, row counts and running balances. Row-level errors contain the sheet, zero-based data-row index and untouched raw row. For a parsed file, `rowsRead === transactions.length + rowErrors.length`.

CSV parsing handles quoted delimiters, escaped quotes, BOM and multiline cells. XLSX uses a narrow OOXML adapter backed by fflate for ZIP and fast-xml-parser for XML. Numeric `<v>` contents remain strings; money never passes through an IEEE double. It reads shared strings, inline/rich strings, sparse cells and textual or Excel-serial timestamps. It rejects formula cells, unsafe archive paths, DTD/entities, excessive archive entries and more than 64 MiB expanded XML. Exported XLSX uses literal string cells, preserving precision without evaluating formulas. This is an exchange-history reader, not a general Excel calculation engine; encrypted, legacy XLS and macro workbooks are unsupported.

Built-in header mappings follow `docs/research/export-formats.md` and its synthetic fixtures. Binance supports current/older spot fills, deposits, withdrawals and known statement income. Binance statement trade/wallet rows overlap dedicated histories and are returned as explicit row errors; use the dedicated histories. Unknown operations, dust/convert grouping and internal transfers require review rather than guessed trades. Original rows remain stored. A statement-only trade reconstruction option is not part of the Phase 1 HTTP contract.

CoinDCX maps Instant Orders and Spot Orders independently. Trade IDs distinguish partial fills. TDS in INR is recorded on buys as well as sells when present. Crypto-quoted gross INR is derived from the report's net conversion with a review flag. GST is recorded only when an explicit GST-in-INR column exists; otherwise it remains unset with a fee-review flag. Unverified wallet layouts and futures/options sheets produce one visible row error per data row.

No-ID source references hash the canonical original row with an occurrence ordinal so two real identical fills survive and reimports remain stable. Different export layouts/formatting of the same trade can produce different references; do not import the same history through multiple layouts without reviewing overlap. Timestamps with explicit UTC headers use UTC and flag a conflicting per-file choice. CoinDCX and generic files use the selected timezone; recipe timezone, if provided, takes precedence. Two-digit Binance years use the documented 20xx convention.

Swap `priceQuote` is expressed per outgoing unit, as required by the existing engine: a crypto-quoted buy disposes the quote itself at quote price `1`; the original exchange price stays in `raw`. Quote/suffix splitting supports common quote assets and explicit delimiters. Ambiguous or unknown fee symbols/amounts produce row errors instead of guessed amounts.

The library research document was not yet present when the ZIP/XML dependencies were selected. No npm `xlsx`, git or tarball dependency is used. CSV/date/decimal handling uses the standard library and existing core helpers.
