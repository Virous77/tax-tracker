# Exchange importers

`importFile({ name, bytes }, { source?, timezone, recipe? })` remains synchronous for CSV/XLSX. `await importFileAsync(file, options)` also accepts PDFs; `await importPdf(file, { timezone, pdfPassword? })` is the PDF-only entry point. The synchronous entry point gives `PdfImportError("pdf_requires_async")` for PDF bytes. Amounts stay decimal strings throughout. No parser makes network calls.

The per-venue registries export independent header detectors and parsers, including `verified: false` for tolerant mappings backed only by descriptive/third-party columns. Every detected kind has a `REPORT_KIND_LABELS` entry. PDF detectors live in `binancePdfReportKinds`, `coindcxPdfReportKinds` and `pdfReportKinds`. Unknown layouts remain on the reviewed generic-recipe path. See `AWAITING_HEADER_SAMPLES` for missing layouts; no P2P, standalone Earn/Buy Crypto, margin/options or futures-order headers have been invented. CoinDCX Wallet History and TDS Summary also await real header samples.

Binance supports current/older/asset-column spot fills, orders, transaction statements, separate and legacy wallet histories, Convert, fiat payments and the documented futures trade/transaction layouts. Earn, distribution, dust, card purchases and internal moves use the statement's documented operations; there is no known separate distribution/dust export. Statement trades/swaps are rebuilt only for one received leg, one spent leg and at most one fee at the same second/account/category. Ambiguous groups and unknown operations become `unknown_type` rows with no guessed monetary legs. Grouped `raw` contains every original leg, and `skippedRows` links constituent legs with their originals. Unknown operations with blank amounts still survive. Known internal moves have no net venue-wide balance effect.

CoinDCX supports Order History and the Trade Report's Instant Orders and Spot Orders, plus tolerant futures/options markers. Fees stay as given; `gstInr` is populated only by an explicit GST column. Long float-noise prices are preserved and flagged. Derivatives are `type: "fee"` with no asset, amount, fee or TDS legs and both `complex_onchain` and `unknown_type`: the current engine creates no spot tax, lots or holdings from these review-only rows. Their complete original contract/P&L fields remain in `raw` for a CA. Core/engine changes are unnecessary for this representation; a separate derivatives review panel can read these flags and originals.

CSV/XLSX detection uses headers rather than extensions. OOXML uses existing fflate/fast-xml-parser dependencies, preserves stored numeric text, and rejects formulas, XML entities, unsafe archives and oversized input. Original row objects, including duplicate columns renamed with `#2`, are retained. No-ID references hash canonical rows plus an occurrence ordinal so identical real fills survive and re-import identities remain stable. Explicit UTC headers/suffixes and Binance filename offsets take precedence over the selected timezone; a bare Binance `Time` without a filename offset is flagged `ambiguous_timezone`. The second order `Time` is the execution/update time, while both times remain in `raw`.

For spreadsheet results, `rowsRead = transactions.length + rowErrors.length + skippedRows.length`. Unsupported workbook sheets retain each original in `rowErrors`; zero-execution orders retain originals in `skippedRows`. `coverage` reports observed first/last ledger timestamps per known kind, for the app to persist alongside each imported file. These are observed bounds, not proof that a date range contains every event.

## Cross-kind reconciliation

`reconcileReportKinds(existing, incoming)` is pure, deterministic and does not mutate or delete either input. `insert` contains accepted new rows, `supersede` identifies old supplementary rows and incoming references replacing them, `duplicates` identifies suppressed incoming supplementary/exact rows, and `ambiguous` leaves new rows in `insert` for the app to flag `possible_duplicate`.

- Same `source + sourceRef` is an exact re-import. Identical fills with distinct occurrence ordinals remain distinct.
- Binance fills win over orders only for the same pair, direction and UTC execution window when summed filled quantity equals executed quantity. Competing orders or quantity mismatches stay ambiguous. Existing partial fills can combine with later incoming fills.
- CoinDCX Spot Orders join Order History by Order ID and complete quantity. Instant Orders are separate. An equal fingerprint without a matching Order ID is only an ambiguity.
- Dedicated Binance fills, wallet/fiat histories and Convert win over matching reconstructed statement events inside their observed coverage. Statement withdrawal totals may include the dedicated withdrawal's additional network fee. Non-unique or mismatched overlap is ambiguous; unrelated periods, income, dust and other exclusive statement operations remain. No whole-period deletion is guessed from sparse ledger rows.
- Rules apply in either import direction. The app must persist supersession links, exclude superseded rows from computation, preserve originals, and link suppressed incoming raw rows to the chosen existing ledger row. It must apply this reconciliation before inserting either channel's duplicates and persist file coverage separately; API/file reconciliation remains the app's existing fingerprint responsibility.

## PDFs

Binance Account Statements produce only `balanceSnapshot: { asOf, timezone, rows: [{ asset, amount, wallet?, raw }] }`; `asOf` is the statement's calendar date. No ledger transactions or cost basis are generated. The layout is unverified: only an explicit Binance Account Statement/date and recognizable Coin/Amount tables are accepted, with an import warning. Aggregated `Others`, negative balances, unknown tables and conflicting dates fail for review instead of becoming fictitious assets. Text items are clustered by vertical position/font height, merged by horizontal gaps, and assigned to columns by overlap/right edges. Wrapped lines, repeated page headers and footer bands are handled. Each balance keeps page, bounding box, cells and wrapped text provenance.

`PdfImportError.code` distinguishes `pdf_password_required`, `pdf_password_incorrect`, `pdf_no_text`, `pdf_unknown_layout`, `pdf_form16a_not_supported`, `pdf_invalid`, `pdf_too_large`, `pdf_timeout` and `pdf_requires_async`. Form 16A text is recognized but its totals are deliberately unsupported until a real layout is verified. `ImportResult.tdsSummary` is reserved for reconciliation-only rows and never contributes transactions; no TDS Summary parser is registered without usable documented headers.

Extraction uses `pdfjs-dist/legacy/build/pdf.mjs` in a Node worker, text only, with eval/font rendering disabled and no URL fetching. Limits are 25 MB, 2,000 pages, 250,000 text items, a 256 MB worker heap and 30 seconds with worker termination. Passwords are passed once and never returned, stored or logged. The app must await the async entry point, supply passwords transiently, map typed errors, and offer explicit saving of snapshots as actual balances. It must ship the built `dist/pdf/worker.js` alongside the importer package.

Dependency: exact `pdfjs-dist@6.5.438`, Apache-2.0, published `2026-11-01T18:22:21.690Z` (confirmed before installation with `pnpm view pdfjs-dist@6.5.438 time --json` on 2026-11-17). Required runtime dependencies and package install scripts: none. Installed and verified with `pnpm install --ignore-scripts`; the workspace's 14,400-minute cooldown and exact-version policy remain unchanged. `ignoredOptionalDependencies` excludes `@napi-rs/canvas`; `pnpm why` shows only pdfjs-dist and no canvas. PDF.js can emit missing-canvas/rendering warnings when loaded; text extraction needs no native canvas.

Synthetic fixtures are documented in `test/fixtures/report-kinds/README.md` and regenerated by `node packages/importers/scripts/build-synthetic-fixtures.mjs` after building. PDF fixtures, including encryption, are generated in memory. `scripts/check-real-exports.mjs` prints aggregate counts only and checks complete row accounting, stable unique references and zero errors, without printing file names or cell values.
