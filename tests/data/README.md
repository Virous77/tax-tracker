# Edge-case input pack

Synthetic files for import, review and export edge cases, plus the generator that writes them.
Nothing here is a real person's export.

```sh
node tests/data/generate.mjs        # writes tests/data/out/, ~28 MB, under a second
```

`tests/data/out/` is gitignored; only the generator and this README are committed. Generation is
deterministic (seeded PRNG, fixed dates, BigInt money), so two runs produce identical bytes.

The generator fails loudly instead of writing a bad file: it stops if `binance-large.csv` is not
exactly 5,000 rows, if any tracked coin balance would go negative, or if `huge.csv` is not over the
25 MB upload limit. INR is not balance-tracked (it is fiat funding, and the app's own balance check
ignores `INR`/`USD`/`EUR`/`GBP`); `USDT` and every coin quote asset are.

## Expected outcomes

Wording used below: **import** is `POST /api/imports` (multipart `file`, `source`, `timezone`),
**preview** is `POST /api/recipes/preview`, **checks** is the `checks` object of that response.
Status codes follow `docs/SPEC.md` §8.

Notes:

- Binance trade-history exports contain no funding deposit, so a file imported on its own shows a
  negative **USDT** balance in checks (`duplicates.csv` reports `-2101.597`). That is a warning for
  review, not a rejection; no coin balance goes negative.
- `malformed.csv`'s four good rows are all BTC buys, so its only negative balance is the same USDT
  artefact.
- The two `generic-*` files are the manual counterpart to the mock LLM: import them, open the recipe
  wizard, and compare the suggested recipe with the columns listed above.
